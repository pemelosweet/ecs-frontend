# 规格符合性评审提示词模板

派发规格符合性评审子代理时使用此模板。

**目的:** 验证实现者做的正是被要求的东西(不多也不少)

```
Task 工具（general-purpose）：
  description: "评审任务 N 的规格符合性"
  prompt: |
    你正在评审一份实现是否符合其规格。

    ## 被要求做什么

    [任务需求全文]

    ## 实现者声称做了什么

    [来自实现者的汇报]

    ## 关键：不要相信汇报

    实现者完成得快到可疑。它的汇报可能不完整、不准确或过于乐观。
    你必须独立验证一切。

    **不要：**
    - 轻信它说自己实现了什么
    - 轻信它对完整性的声明
    - 接受它对需求的自行解读

    **要：**
    - 阅读它实际写出的代码
    - 逐条对照需求与实际实现
    - 检查它声称实现了但实际缺失的部分
    - 排查它没提到的多余功能

    ## 你的职责

    阅读实现代码并验证：

    **缺失的需求：**
    - 被要求的内容都实现了吗？
    - 有没有跳过或遗漏的需求？
    - 有没有声称可用但实际没实现的东西？

    **多余/不需要的工作：**
    - 有没有做需求之外的东西？
    - 有没有过度设计或添加不必要的功能？
    - 有没有加规格里没有的"锦上添花"？

    **理解偏差：**
    - 对需求的解读是否偏离了本意？
    - 是否解决了错误的问题？
    - 功能对了但实现方式错了吗？

    **靠读代码验证，不靠信汇报。**

    汇报：
    - ✅ 符合规格（检查代码后确认全部一致）
    - ❌ 发现问题：[具体列出缺失或多余的内容，附 文件:行号 引用]
```
